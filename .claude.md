# LDC DCompute Metal Backend — GSoC 2026

## Project Goal

Extend LDC to generate Apple Metal compute shaders from D `@compute` code,
enabling D to run natively on Apple GPUs. "Shader" here refers to GPU compute
programs (not graphics vertex/fragment shaders) — the project focuses on
general-purpose GPU computing.

Mentor: Nicholas Wilson. Reference PR: [#4958](https://github.com/ldc-developers/ldc/pull/4958) (Vulkan backend).

## DCompute Semantic Analysis

`dcomputeSemanticAnalysis()` in `gen/semantic-dcompute.cpp` enforces GPU
restrictions on `@compute` modules:

- Bans: classes, interfaces, asm, typeid, global variables, synchronized,
  associative arrays, `new`, `delete`, `throw`, string literals
- Module check: `visit(CallExp *)` verifies called functions are in `@compute`
  modules. Template-instantiated functions skip this check via
  `isInstantiated()` since their `getModule()` reflects the declaration site,
  not where the self-contained code actually runs.

## Gotchas

- **Always use `@kernel()` with parentheses.** `@kernel` without `()` is
  silently not registered as a kernel entry point, and GlobalDCE removes
  the function from the AIR output.

## Bug Fixes

### CondExp rvalue + GlobalPointer on Metal

Rvalue `(idx < N) ? input[idx] : 0` produced wrong zeros on Metal because
`visit(CondExp)` always used the lvalue pointer-merge path (`condtmp` +
`DSpecialRefValue`), and `getRVal()` reloaded via generic `load ptr`, dropping
`addrspace(1)`.

Fix in `gen/toir.cpp`: split on `e->isLvalue()` — rvalue branches store values
into a typed temp; lvalue path unchanged. Codegen test:
`tests/codegen/dcompute_metal_condexp.d`.

See `docs/ISSUE_condexp_metal_globalpointer.md` and
`docs/condexp-codegen-walkthrough.md`.

**Not fixed:** lvalue CondExp with GlobalPointer on both branches
`(c) ? input[i] : input[j]`.

### Issue #5116: Struct with static array field caused crash

`struct S { float[N] data; }` in a `@compute` module caused DMD to generate
`__xopEquals`, which triggered instantiations of `__equals`/`isEqual` from
`core.internal.array.equality`. The walker then reported spurious errors on
nested calls, and crashed on a function-pointer indirect call (`e->f == null`).

Fix (2 changes in `gen/semantic-dcompute.cpp`):
1. Null guard in `visit(CallExp *)` for indirect calls
2. Template-instantiated functions skip the module check (`isInstantiated()`)

Test: `tests/compilable/issue5116.d`. See `docs/ISSUE_5116_NOTES.md` for full analysis.
